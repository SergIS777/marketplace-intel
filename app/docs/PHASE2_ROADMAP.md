## 0. Правовой контекст (обязательно к прочтению ДО начала)

### Telegram в России: что закрыто

1. ФЗ №41-ФЗ от 01.04.2025 (действует с 1 июня 2025): банки, маркетплейсы,
   агрегаторы объявлений, операторы связи НЕ могут общаться с клиентами через
   Telegram и WhatsApp.
2. ФАС, март 2026: реклама в Telegram признана нарушением закона «О рекламе»,
   штрафы до 500 000 ₽ за одно нарушение.
3. Минцифры, декабрь 2024: готовит запрет на использование Telegram и других
   зарубежных мессенджеров в рабочих целях с 1 сентября 2026.

### Что это значит для нас

- Telegram-бот работает сейчас: мы не банк и не маркетплейс, но клиент
  может попасть под 41-ФЗ.
- Стратегически: Telegram-бот остаётся демо-каналом и «пультом владельца».
  Для общения с покупателями (отзывы, чаты) обязательна миграция на собственное
  Android-приложение или российские мессенджеры (VK, Max).
- План:
  - Фаза 2.1: Telegram-бот как внутренний пульт (владелец магазина)
  - Фаза 2.2: Android-приложение с LLM-ассистентом (обёртка вокруг нашего бэкенда)
  - Фаза 2.3: ответы на отзывы через Seller API (POST /api/v1/feedbacks/answer) —
    там Telegram не нужен, ответы идут в карточку WB

### 152-ФЗ: персональные данные

Текущая система 152-ФЗ не нарушает: парсим только публичные данные.
С Seller API появятся реальные данные покупателей (имя, адрес ПВЗ)
в заказах FBS — это уже персональные данные. Решения:
- хранение только на сервере в РФ (VPS уже в РФ)
- логирование без ФИО (обезличенные события)
- договор с клиентом на обработку ПДн (шаблон приложим)

## 2. Регистрация в WB Partners и тестовый токен

Шаг 1. Регистрация:
1. seller.wildberries.ru → «Регистрация» → тип «Продавец» (ИП или ООО)
2. Для теста достаточно ИП на УСН — быстрее и дешевле
3. Нет ИП — регистрируешь на своё имя, потом передаёшь токен клиенту

Шаг 2. Тестовый токен:
1. WB Partners → организация → «Интеграции по API»
2. «+ Создать токен» → тип «Тестовый»
3. Выбрать категории доступа (для теста — все)
4. Скопировать токен СРАЗУ (показывается один раз)
5. Сохранить в .env:

    WB_SELLER_API_TOKEN_TEST=...
    WB_SELLER_API_BASE_URL=https://common-api-sandbox.wildberries.ru

Шаг 3. Проверка подключения (python):

    import requests
    headers = {'Authorization': WB_SELLER_API_TOKEN_TEST}
    r = requests.get('https://common-api-sandbox.wildberries.ru/ping', headers=headers)
    print(r.status_code, r.json())

Ожидаемо: 200 и {"data": "OK"}.

## 3. Три модели работы: FBO / FBS / DBS

| Модель | Где товар | Кто хранит/собирает/везёт | Кому подходит |
|---|---|---|---|
| FBO | Отгружено оптом на склад WB | WB хранит, собирает, везёт | Ходовой товар с предсказуемым спросом |
| FBS | На складе продавца | Продавец хранит и собирает, WB везёт | Длинный хвост, крупногабарит, тест новых SKU |
| DBS | На складе продавца | Продавец всё сам, своей курьеркой | Редкость, специфика |

Архитектурное решение: вариативность через конфиг. Каждая модель — секция в
config/<store>.yaml, которая говорит системе, какие модули включать.

Пример конфига (yaml, отступом):

    store:
      name: DORFHAUS
      model: FBS              # FBO | FBS | DBS
      wb_token_type: test     # test | production
      integration:
        accounting: 1C_Fresh  # none | 1C_Fresh | 1C_OnPremise | MoySklad
        marking: chestny_znak # none | chestny_znak
      fbs:
        warehouse_id: 123456
        packing_deadline_hours: 24
      fbo:
        warehouses:
          - id: 789
            name: Коледино
            priority: 1
      dbs:
        courier_service: CDEK

Модули, включаемые по модели:

| Модуль | FBO | FBS | DBS |
|---|:---:|:---:|:---:|
| Синхронизация остатков WB и 1С | да | да | да |
| Сборка заказов (FBS-лента) | — | да | — |
| Планирование поставок FBO | да | — | — |
| Курьерская интеграция | — | — | да |
| Маркировка Честный ЗНАК | если применимо | если применимо | если применимо |
| Возвраты покупателей | да | да | да |
| Тарифы (логистика, хранение) | да | да | да |
| Аналитика продаж (funnel) | да | да | да |

Псевдокод выбора ветки (python):

    class StoreEngine:
        def __init__(self, config):
            self.config = config
            self.model = config['store']['model']
            self.modules = self._select_modules()

        def _select_modules(self):
            modules = [AccountingSync, ReviewResponder, TariffsMonitor, AnalyticsReporter]
            if self.model == 'FBO':
                modules.append(FBOSupplyPlanner)
            elif self.model == 'FBS':
                modules.extend([FBSAssemblyQueue, FBSStockSync])
            elif self.model == 'DBS':
                modules.extend([DBSCourierIntegration, DBSPacking])
            return modules

        def run(self):
            for mod in self.modules:
                mod(self.config).tick()

## 4. Интеграция с 1С

### Какие бывают 1С у клиентов

| Вариант | Где | Как подключаемся |
|---|---|---|
| 1С:Фреш (облако) | Серверы 1С | HTTP-сервис 1С, REST |
| 1С on-premise | Сервер клиента | HTTP-сервис 1С, файлы обмена |
| МойСклад | Облако | REST API МойСклад |
| Excel / Google Sheets | Где угодно | Google Apps Script или CSV |

### Тестовые среды 1С (для разработки)

- 1С:Фреш: демо 30 дней бесплатно на 1cfresh.com; конфигурации: Бухгалтерия,
  УНФ, Управление торговлей, Розница; данные после теста сохраняются при покупке.
- Онлайн-демо базы: v8.1c.ru — Бухгалтерия 8 в браузере и все типовые конфигурации.
- Учебная версия 1С:Предприятие 8.3: платформа бесплатно для обучения.

### Схема обмена

    [1C]  <->  [наша система]  <->  [WB Seller API]
     учёт товаров,   оркестратор,      заказы/остатки/цены
     себестоимость,  логика,           поставки/отчёты
     документы       LLM-ответы        отзывы/вопросы

Минимальная интеграция Фазы 2:
1. Раз в 15 минут: остатки 1С → WB (PUT /api/v3/stocks/{warehouseId})
2. Раз в час: новые заказы WB → 1С (через HTTP-сервис 1С)
3. Раз в час: цены 1С → WB (POST /api/v2/upload/task)
4. По событию: ответ на отзыв из нашей системы (LLM + few-shot)

### Обезличенный контракт обмена (python)

    class AccountingAdapter:
        """Адаптер к любой учётной системе"""
        def get_stock(self, sku: str) -> int: ...
        def get_cost(self, sku: str) -> float: ...
        def push_order(self, order: dict) -> str: ...
        def push_return(self, order_id: str) -> str: ...

    class OneCFreshAdapter(AccountingAdapter): ...
    class MoySkladAdapter(AccountingAdapter): ...
    class GoogleSheetsAdapter(AccountingAdapter): ...

Клиент выбирает адаптер через конфиг, мы не переписываем код.

## 6. Ключевые эндпоинты Seller API

Отзывы и вопросы (наш главный козырь):

    GET   /api/v1/feedbacks                   — список отзывов
    GET   /api/v1/new-feedbacks-questions     — непросмотренные отзывы и вопросы
    POST  /api/v1/feedbacks/answer            — ответить на отзыв (РАБОТАЕТ!)
    PATCH /api/v1/feedbacks/answer            — отредактировать ответ
    POST  /api/feedbacks/v1/pins              — закрепить отзыв
    GET   /api/v1/claims                      — заявки на возврат

Сценарий human-in-the-loop через Seller API:
1. GET /api/v1/new-feedbacks-questions — новые отзывы
2. наш llm_reviewer пишет черновик (few-shot на базе source=human)
3. бот показывает черновик владельцу
4. владелец жмёт [одобрить вариант LLM] или пишет свой
5. бот шлёт POST /api/v1/feedbacks/answer — ответ попадает в карточку WB

Остатки и поставки:

    PUT  /api/v3/stocks/{warehouseId}         — обновить остатки
    GET  /api/v3/stocks/{warehouseId}         — прочитать остатки
    POST /api/analytics/v1/stocks-report/wb-warehouses — остатки на складах WB (FBO)
    POST /api/v1/supplies                     — создать поставку (FBO)
    GET  /api/v1/warehouses                   — список складов

Заказы FBS (сборка):

    GET  /api/v3/orders/new                   — новые сборочные задания
    GET  /api/v3/orders                       — информация о заданиях
    POST /api/v3/orders/stickers              — стикеры для сборки

Аналитика (чего нет в публичных API):

    POST /api/analytics/v3/sales-funnel/products/history — воронка по дням
    GET  /api/v1/supplier/sales               — реальные продажи (не прокси-темп)
    GET  /api/v1/analytics/antifraud-details  — самовыкупы
    POST /api/v2/search-report/product/search-texts — поисковые запросы по товару
    POST /api/finance/v1/sales-reports/detailed — отчёт о реализации

Тарифы:

    GET /api/tariffs/v1/acceptance/coefficients
    GET /api/v1/tariffs/box
    GET /api/v1/tariffs/commission
    GET /api/v1/tariffs/return

## 7. Android-приложение: миграция с Telegram

Почему неизбежно: запреты Telegram делают бота рискованным каналом для работы
с покупателями. Для пульта владельца Telegram пока работает, но стратегически
правильно — собственное приложение.

Архитектура:

    [Android-приложение]  <-HTTPS->  [наш FastAPI-бэкенд]  <->  [WB Seller API]
         UI владельца                     LLM + бизнес-логика
         (Jetpack Compose)                (та же, что сейчас)

Бэкенд переиспользует 100% текущей Python-логики: меняется только транспорт
с Telegram на REST API.

Стек Android:
- язык: Kotlin
- UI: Jetpack Compose
- LLM: на бэкенде (через наш API) или локально (MLC-LLM)
- локальная БД: Room + синхронизация с бэкендом
- push: Firebase Cloud Messaging (FCM)

MVP-экраны:
1. «Мои товары» (остатки, цены, темп)
2. «Конкуренты» (наш модуль из публичных API)
3. «Отзывы» (LLM-черновики, кнопки одобрить/напишу сам)
4. «Заказы FBS» (лента сборочных заданий, сканер штрих-кода)
5. «Поставки FBO» (планирование, статусы)
6. Push-уведомления вместо Telegram-дайджестов

Оценка разработки:

| Вариант | Стоимость | Срок |
|---|---|---|
| Своими силами (ты + Android AI) | бесплатно | 2–3 месяца |
| Фрилансер Android | 150 000–250 000 ₽ | 2–3 месяца |
| Агентство под ключ | 500 000–1 000 000 ₽ | 3–4 месяца |

Публикация: RuStore (не Google Play из-за санкций).

## 10. Что НЕ меняется в нашей архитектуре

- публичные API-модули остаются: конкуренты, темп (как прокси), поиск карточек
- LLM-ядро llm_reviewer: тот же few-shot, только источник отзывов меняется
- дашборд Streamlit: новые секции добавляются, старые остаются
- cleanup и retention: та же логика
- конфиг-дривен подход: новый магазин = новый yaml

Меняется только источник данных внутри коллекторов плюс новый канал доставки
(Android вместо Telegram).

## 13. FAQ для собеседований

Q: Как вы работаете с Seller API?
A: Через open-source SDK (MIT), фиксированная версия, типизация pydantic.
   Ретраи и rate-limiting встроены. Тестовый контур через sandbox.

Q: Что если у клиента нет 1С?
A: Адаптеры под МойСклад, Google Sheets, CSV. Минимум — обмен через Excel.

Q: FBO или FBS?
A: Конфиг-дривен: одна кодовая база, три ветки логики по флагу в yaml.

Q: Как отвечать на отзывы через систему?
A: LLM пишет черновик на few-shot базе (голос владельца), владелец одобряет,
   бот шлёт POST /api/v1/feedbacks/answer — ответ попадает в карточку WB.

Q: Почему не Telegram-бот для клиентов?
A: ФЗ-41 и запреты ФАС 2025–2026. Telegram — только внутренний пульт владельца.
